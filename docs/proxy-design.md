# 代理服务器管理

## 一、功能说明

* 负责管理代理服务器，支持 http 和 socks5 代理。
* 按代理组管理，一个代理组包含多个代理地址。
* 代理组内代理地址顺序即为优先级，优先级高者优先被调度。
* 同一代理地址可被多个代理组引用；代理地址的统计信息、错误信息和可用状态全局唯一，不因代理组不同而重复记录。
* 支持按应用维度评估代理地址可用性，即同一代理地址可能网络可用，但对某个应用不可用。
* 支持代理地址的实时调度、错误统计、内存/数据库分层存储、熔断标记与恢复。

## 二、名词定义

* **代理地址**：规范化后的唯一标识，例如 `scheme://host:port` 或 `host:port`。同一地址在不同代理组中出现时，视为同一代理地址。
* **代理组**：一组有序代理地址的集合，顺序即优先级。
* **网络错误**：代理地址本身不可达、连接失败、超时、TLS 握手失败、代理层返回错误等，导致请求无法正常通过代理到达目标应用。
* **应用错误**：代理网络本身可用，但目标应用请求失败，例如业务错误码、鉴权失败、IP 被限制、应用层拒绝等。具体错误码映射可配置。
* **网络可用**：代理地址当前可正常建立网络连接或通过主动探测。
* **应用可用**：代理地址对某个具体应用可用，维度为“代理地址 + 应用”。
* **半开状态**：代理地址被标记不可用后，经过冷却期，允许少量真实业务请求尝试，用于验证是否恢复。应用错误不主动探测，只能通过真实业务请求进入半开验证。

## 三、核心需求

### 1. 代理组与优先级

* 代理组内代理地址按配置顺序排列，顺序即优先级。
* 调度时默认从高优先级到低优先级选择第一个可用代理。
* 若高优先级代理不可用，则自动降级到下一个代理。
* 代理组只维护代理地址的有序引用；代理地址的统计和状态由全局统一管理。

### 2. 错误分类

错误状态分为两类：

* **网络错误**：代理地址自身网络不可用。
* **应用错误**：代理地址无法使用某个应用，但网络本身可能仍可用。

网络错误影响该代理地址的所有应用；应用错误只影响对应应用，不影响其他应用。

### 3. 统计记录

代理地址需要记录错误信息。若两个代理组引用相同代理地址，只记录一份，按代理地址全局去重。

记录内容包括：

* 网络请求次数和失败次数。
* 各类应用的请求次数和失败次数。
* 连续失败次数、最后失败时间、最后成功时间。
* 错误类型：网络错误、应用错误。
* 当前可用状态：网络可用/不可用、应用可用/不可用。
* 半开状态、冷却时间、探测信息等。

### 4. 存储策略

错误信息同时记录到内存和数据库。

* **内存**：
  * 只记录最近 10 分钟以内的信息。
  * 按 1 分钟分段记录。
  * 用于实时调度、状态判断和熔断恢复。
  * 当分钟桶超过 10 分钟或达到容量阈值时，将过期数据聚合写入数据库，并清理内存。
* **数据库**：
  * 按 10 分钟分段记录。
  * 用于长期统计、分析和审计。
  * 数据库存储不直接参与实时调度，实时调度以内存数据为准。

### 5. 可用状态标记

代理地址需要标记可用状态：

* **网络可用状态**：全局状态，网络可用 / 网络不可用。
* **应用可用状态**：按应用维度，应用可用 / 应用不可用。
* 可扩展状态：正常、熔断中、半开、探测中。

调度时，对当前应用而言，代理地址必须满足：

1. 网络可用；
2. 对该应用可用，或处于允许真实业务试探的半开状态。

### 6. 调度策略

代理组内调度策略根据内存中的出错记录和可用状态决定。

建议调度流程：

1. 获取代理组内按优先级排序的代理地址列表。
2. 过滤掉网络不可用的代理地址。
3. 针对当前应用，过滤掉该应用不可用的代理地址。
4. 对处于半开状态的代理地址，可按低概率或小流量放行真实业务请求。
5. 在剩余可用代理中，按组内顺序选择第一个代理。
6. 若全部不可用，则进入降级策略：
   * 优先选择半开代理进行真实业务试探；
   * 或选择近期失败率最低的代理；
