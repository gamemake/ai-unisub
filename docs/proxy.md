# Unisub Proxy Group

## 功能说明

- 负责管理代理服务器，按代理组组织；一个组包含多个有序代理地址，地址顺序即优先级，高优先级可用地址优先被调度。
- 代理组只维护地址的有序引用。同一代理地址可以被多个组引用，其统计、错误信息和可用状态全局唯一，不按组重复记录。
- 区分网络可用与应用可用：同一地址可能网络可用，但无法访问某个应用。网络错误影响该地址的所有应用，应用错误只影响对应应用。
- 支持实时调度、错误统计、内存／数据库分层存储、不可用标记、熔断和恢复。网络错误允许主动探测；**应用错误不主动探测，只通过对应应用的真实业务请求验证恢复**。

本文融合功能约束、策略建议与当前实现。当前已实现分钟窗口失败率熔断、网络／应用独立冷却、网络自动退避探测、真实请求半开及健康快照落库；策略建议中的多级覆盖、概率放行等可选扩展不代表已有配置项。准确的接口与默认值见“实现接口与策略”。

## 架构与领域模型

### 设计范围与实现位置

`internal/proxy` 承载代理管理能力，当前实现接口与默认策略见“实现接口与策略”。代理组沿用原管理路由和 JSON 表示；基础代理工具不再位于 Common，代理 Manager 不再位于 Service。

代理包独立负责代理组配置、地址调度、探测、错误分类、可用状态、统计和恢复；不负责 Web 登录、HTTP 管理路由、OAuth 协议或 AI 请求体转换。

### 包边界与依赖

目录按职责划分为：

```text
internal/proxy/
  types.go       代理、代理组、应用维度、错误与统计模型
  endpoint.go    代理对象构造、内部 URL 解析与校验
  transport.go   根据代理对象配置 HTTP 传输
  manager.go     配置管理和生命周期
  scheduler.go   优先级选择与可用性判定
  health.go      主动探测、冷却与半开控制
  stats.go       内存时间桶和持久化聚合
  log.go         错误与状态变化日志、敏感信息脱敏
  store.go       持久化接口
```

- `proxy` 可以使用标准库和 `common`，不导入 `service`、`unisub`、`oauth`、`aiprovider` 或具体数据库驱动。
- `proxy` 定义自身领域模型及最小 Store 接口；`database` 提供满足该接口的适配能力，负责领域模型与持久化表示的转换。
- `service` 创建并注入代理 Manager，向模块提供能力，关闭时负责释放 Manager 拥有的资源。
- `unisub/api` 负责请求解析、管理员权限和 HTTP 响应，不拥有调度状态。
- AIProvider 通过调用方定义的 resolver/reporter 接口使用代理。应用标识由调用方传入，代理包不枚举具体 AI 厂商。
- `oauth` 显式依赖 `proxy`，通过参数接收代理对象；`proxy` 不反向依赖 `oauth`，因此不形成循环依赖。AIProvider 和应用层同样使用代理对象，不通过 Context 隐式传递代理字符串。
- URL 解析和校验封装在代理对象的构造过程中，不单独暴露解析工具函数；`common` 下不包含 `proxy.go`，也不提供代理函数或代理兼容转发入口。
- 代理 ID 只表示代理资源，不让调用记录等无关业务依赖代理包生成 ID。

### 领域模型

| 概念 | 契约 |
| --- | --- |
| 代理地址 | 规范化后的地址及认证身份共同确定唯一代理；支持 HTTP、HTTPS、SOCKS5、SOCKS5H |
| 代理组 | 有序代理引用集合，组内顺序即优先级；包含启用状态和重试策略 |
| 网络状态 | 按代理地址全局保存，表示代理本身是否可达 |
| 应用状态 | 按“代理地址 + 应用标识”保存，表示能否访问指定应用 |
| 错误记录 | 区分网络错误和应用错误，保留计数、时间与受控错误分类 |
| 半开状态 | 冷却后允许有限真实请求验证恢复，不等同于完全可用 |

相同代理被多个组引用时，共享网络状态、应用状态与统计，不按组重复记录。规范化不能合并不同认证身份，也不能改变 `socks5` 与 `socks5h` 的 DNS 语义。管理输入要求带 Scheme；缺少 Scheme 的地址不推断协议。

### 代理对象与显式传递

公共接口不再包含 WithHTTPProxy、HTTPProxyFrom、ParseHTTPProxy，不设置代理 Context key，也不在其他包保留这三个函数的转发包装。Context 仅承载请求取消和超时，不承载代理配置。

代理包提供已校验、不可变的代理对象。公共构造接口：

```go
// Endpoint 内部封装代理地址，不向调用方暴露可变的 URL。
func NewEndpoint(address string) (*Endpoint, error)
```

构造时统一去除首尾空白，并校验 Scheme、Host 和非空 Hostname；允许 http、https、socks5、socks5h。当前实现拒绝 Query、地址内空白、Fragment 和不透明 URL；显式端口必须在 1–65535 之间。空地址不构成有效 Endpoint，未指定代理由调用参数中的 nil 明确表示。移除独立解析函数不等于取消输入校验，构造成功也不代表代理已通过可用性探测。

代理包根据 Endpoint 配置独立的 HTTP 传输实例，保留调用方的超时等设置，不修改共享客户端或全局 Transport。不同授权流程的代理选择不能互相影响。

OAuth 启动参数显式携带 Endpoint，Session 保存本次选定的不可变对象；Complete/Poll 使用该对象配置协议请求，无需从 Context 恢复代理。无 Session 的刷新或撤销也通过显式参数接收代理。代理选择、客户端构造与凭据存储相互独立，详见 [OAuth](oauth.md)。

验证覆盖地址构造、未指定代理、非法输入、并行请求的代理隔离、Session 代理绑定，以及 Context 取消和超时对出站请求的作用，不再验证代理 Context 读写。

## 调度与健康策略

### 对外能力

以下能力由 Manager 提供：

| 能力 | 输入与输出语义 |
| --- | --- |
| 代理组管理 | 查询、创建、保存、删除有序代理引用；校验地址、重复引用和重试参数。创建由存储分配 ID，保存要求已有正数 ID |
| 选择代理 | 输入 Context、组 ID、应用标识和已尝试代理；输出选中代理或明确的不可用错误 |
| 报告结果 | 输入代理标识、应用标识、成功或错误分类、时间；更新共享状态及统计 |
| 主动探测 | 探测已保存代理或未保存 URL；探测器可注入，不绑定业务 Handler |
| 查询状态与统计 | 按地址、应用及时间范围返回快照，不暴露可变内部状态 |
| 关闭 | 停止自有任务、完成统计持久化并释放资源；重复关闭安全 |

空代理组表示不指定代理；指定的组不存在或没有可用代理时返回错误，不静默绕过代理直连。探测和调度沿用调用 Context，禁止无界等待。

### 调度流程与重试边界

1. 按组内配置顺序读取启用的代理，排除本次请求已尝试的地址。
2. 检查网络状态，跳过仍在冷却或没有半开配额的网络不可用地址。
3. 检查当前应用状态，跳过仍在冷却或没有半开配额的应用不可用地址；冷却结束不等于自动恢复可用。应用半开只接收真实业务请求。
4. 在正常候选及满足独立准入条件的半开候选中，按组内优先级选择第一个，并原子占用必要的半开配额，不按轮询顺序分配。
5. 没有候选时返回不可用；不以“最低失败率”为由忽略不可用标记。半开请求必须满足独立准入条件。

网络错误影响该地址的所有应用；应用错误只影响对应应用。网络恢复可通过主动探测或真实请求确认；应用错误不通过通用网络探测清除，只通过对应应用的真实请求验证。

目标调度以可用状态为第一依据、组内优先级为第二依据，最近 10 分钟内的失败率和连续失败次数用于状态判断，不将数据库历史统计作为实时选择依据。正常调度要求网络可用且当前应用可用；网络或应用半开属于受控试用例外，不作为普通可用流量放行。高优先级地址恢复后自动重新获得优先选择资格。

全部不可用时采用明确的失败策略：仅在有符合冷却、配额及请求时限要求的半开候选时尝试，否则立即返回不可用，由上层决定处理。不选择尚在冷却中的“最低失败率”地址，不无限重试、不积压等待，也不自动直连。

重试次数受组配置与可用替代代理数量限制。是否能够重放请求体、请求是否可重试、响应是否已经发出，由上游调用方决定；代理包不能自行重发 HTTP 请求。

### 错误分类与统计口径

网络错误包括代理不可达、连接失败、连接或隧道建立超时、代理连接阶段 TLS 握手失败以及代理层连接异常等，即请求无法正常通过代理到达目标应用。目标应用返回的拒绝、鉴权失败、IP 限制及业务错误等属于应用层结果，由调用方按协议分类；不是所有非 2xx 响应都代表代理不可用。TLS 错误和超时须结合发生阶段归因，不能把所有目标端错误都认定为代理网络故障。

统计和状态信息包括：

| 维度 | 记录内容 |
| --- | --- |
| 代理地址 | 网络请求次数、网络失败次数、连续网络失败次数、最后成功／失败时间、网络可用状态 |
| 代理地址 + 应用 | 该应用请求次数、应用失败次数、连续应用失败次数、最后成功／失败时间、应用可用状态 |
| 错误与恢复 | 网络／应用错误分类、受控错误码及摘要、正常／熔断／半开状态、冷却截止时间、半开占用量、探测时间和结果 |

错误信息不得包含代理密码、访问令牌等敏感数据。建议将一次真实出站尝试作为计数单位，而不是将“被候选筛选”计为请求；跨组只向全局唯一地址记录一次。重试产生新的出站尝试，分别计数；客户端取消不累计健康失败。

目标统计应区分业务请求与主动探测：探测单独保留次数和结果，不计入业务应用统计。网络失败只触发网络熔断，不能同时增加各应用的连续应用失败次数；收到有效应用响应说明网络路径已打通，即使该响应属于应用错误，也不能计作网络失败。计算应用失败率时应以已到达应用层、能够判定应用结果的尝试为分母，避免网络故障扭曲应用健康判断。

### 日志记录原则

代理相关的所有错误均须记录日志，不依赖是否发生状态变化或是否达到熔断阈值。日志不改变健康统计口径或持久化契约。

- 错误和状态变化独立记录：一次失败导致熔断时，分别记录错误日志和状态转换日志；未触发状态变化的错误也必须记录。
- 同一次错误只记录一次：在拥有完整上下文的位置记录，避免同一错误在底层和上层传播时重复打印；每次重试失败属于独立事件，须分别记录。
- 保留具体原因：除网络／应用错误分类外，还须记录具体错误原因；由掌握原始错误的调用方记录，或补充内部错误上报参数。HTTP 失败同时记录状态码，不仅输出错误分类。
- 不泄露凭据：代理 URL 和错误文本统一脱敏，不输出代理用户名、密码、认证头、访问令牌或响应正文。
- 正常分支不算错误：遍历时跳过禁用、冷却中或无半开配额的代理，不逐条打印错误日志；最终无法选出代理时，记录调度失败及原因摘要。请求取消或管理器已关闭导致的操作失败仍须记录，但应明确标为取消或生命周期事件，不计为代理健康失败。

### 不可用标记（目标策略）

网络和应用分别计算，不共用连续失败计数和冷却状态。对各自的统计窗口，满足以下任一条件时熔断：

- 连续失败次数达到配置阈值；此条件不需要等待窗口最小样本数。
- 窗口内有效请求数达到最小样本数，且失败率达到配置阈值。样本不足或无请求时不按失败率熔断。

窗口可选最近 1、5、10 分钟，使用内存分钟桶近似滑动窗口，并明确按分钟对齐的边界。网络熔断设置地址的网络不可用状态；应用熔断仅设置 `(代理地址, 应用)` 不可用。HTTP 状态码和业务错误码的映射建议可配置，由调用方适配器转为代理包的统一错误分类；请求参数错误、用户凭据失效等与代理地址无关的错误不应仅凭状态码触发共享地址熔断。

### 网络错误恢复（目标策略）

1. 网络不可用后进入冷却期，所有应用的普通业务调度均跳过该地址。
2. 冷却结束后允许主动网络探测。可根据代理协议使用 TCP 连接、HTTP CONNECT 或经代理访问健康检查地址；TCP 成功只能证明端口可达，完整恢复判断应覆盖实际使用的代理转发路径。
3. 探测失败继续保持不可用，并增加退避；建议间隔为 30 秒、1 分钟、2 分钟、5 分钟、10 分钟，封顶并加入随机抖动。
4. 连续探测成功达到阈值后恢复网络可用，清零连续网络失败和退避计数。也可允许受限真实请求进行网络半开验证，但须使用同一网络恢复状态机，不能与探测并发重复放行。
5. 网络恢复不清除任何应用熔断；应用须独立验证。探测设置超时、并发上限和每地址单任务约束，不在全局锁内等待网络结果。

### 应用错误恢复（目标策略）

1. 对受影响的 `(代理地址, 应用)` 设置冷却期，其他应用不受影响。
2. 冷却结束后进入可半开试用阶段，只从该应用真实业务流量中选取少量请求，不生成额外应用探测请求。
3. 半开准入可配置为每 N 个请求放行一个、按低概率放行或固定小流量配额；无论使用哪种方式，都须有原子的半开并发上限。建议初始上限为每个地址、每个应用 1 个在途请求。
4. 连续真实业务成功达到阈值后恢复应用可用，清零连续应用失败；应用失败则重新熔断、重置成功计数和冷却时间。试用期间发生网络失败只更新网络健康，不能据此认定应用仍然故障；取消请求释放配额，不算恢复成功或失败。
5. 长时间没有该应用流量时保持未恢复状态，直到真实请求触发半开验证。旧失败桶过期不自动解除熔断。

### 配置项建议（目标参数）

下表为建议起始值，不覆盖后文列出的当前 `DefaultPolicy`。网络与应用参数应独立配置。

| 配置项 | 说明 | 建议起始值或选项 |
| --- | --- | --- |
| 统计窗口 | 内存健康判断窗口 | 1／5／10 分钟，建议默认 5 分钟 |
| 最小样本数 | 按失败率熔断所需样本 | 5 |
| 网络失败率阈值 | 网络窗口失败率 | 50% |
| 应用失败率阈值 | 应用窗口失败率 | 50% |
| 连续网络失败阈值 | 网络连续失败次数 | 3 |
| 连续应用失败阈值 | 应用连续失败次数 | 3 |
| 网络冷却时间 | 首次网络熔断冷却 | 30 秒 |
| 网络探测间隔 | 主动探测指数退避范围 | 30 秒至 10 分钟 |
| 网络恢复成功次数 | 连续网络探测成功数 | 2 |
| 应用冷却时间 | 应用熔断冷却 | 5 分钟 |
| 应用半开比例 | 真实业务试用比例 | 5% 或 1/N |
| 半开并发上限 | 单地址网络／单地址单应用试用上限 | 各 1 |
| 应用恢复成功次数 | 连续半开真实请求成功数 | 2 |

建议全局提供默认值，网络策略可按代理地址覆盖，应用策略可按应用及 `(代理地址, 应用)` 覆盖。若提供组级覆盖，组可独立控制重试次数和准入流量，但共享地址的健康阈值必须先解析为唯一有效策略；冲突配置应拒绝或要求显式地址级策略，不能根据“最近来自哪个组”改变全局熔断规则。

## 存储与并发

- 内存保留最近 10 分钟的 1 分钟桶，用于实时调度和恢复判断。
- 数据库按 10 分钟桶保存聚合统计，用于历史分析；实时选择不扫描历史统计。
- 过期或达到容量阈值的桶聚合持久化，成功后才能清理相应内存数据；写入失败保留重试依据。
- 持久化以代理、应用和桶时间等稳定标识保证重复写入不会重复累计。容量上限和故障处理应明确，不能无限积压。
- 组配置、全局状态、半开配额和统计快照需要并发一致性；网络探测不在全局状态锁内执行。
- Store 接口只涵盖代理配置和聚合统计所需操作，不接收整套 `database.Database` 或 SQLite 连接。

### 时间桶、落库与恢复边界

- 分钟桶和数据库 10 分钟桶建议统一按 UTC 对齐，使用左闭右开区间，例如 `[12:00, 12:10)`。同一数据库桶内的分钟数据聚合到同一地址、应用键下。
- “内存只保留最近 10 分钟”约束实时统计明细，不意味着 10 分钟后删除熔断状态、冷却时间或半开配额。过期分钟桶退出调度窗口，未成功落库的聚合进入独立、有界的待写区，不再参与实时失败率计算。
- 达到容量阈值时可以提前刷写聚合，但不能无声删除仍在窗口内、用于调度的统计；无法继续维护窗口和待写数据时应明确背压或拒绝新增统计序列。禁止数据库写失败后直接清空数据，也禁止无限堆积。
- 幂等写入应采用稳定来源标识和绝对快照，或使用唯一批次标识的增量事务；不能对重试批次重复累加。历史查询若合并内存与数据库，必须按来源和桶去重，避免把已落库快照再次相加。
- `HealthStore` 持久化按地址与应用唯一的健康快照，包含最后错误类别、连续失败、时间、冷却、半开和独立探测计数；数据库 `proxy_health` 以覆盖方式写入，不按组复制。快照用于历史检查，不恢复进程的实时熔断状态。逐次错误正文和完整状态转换事件不是当前存储契约。
- 正常关闭须刷新待写统计；仅靠内存和定时刷新不能保证异常进程退出时零丢失。若要求异常退出也不丢失，应另行采用持久化写前日志或可靠队列，不将这一保证归于当前分钟刷新机制。

## 实现接口与策略

以下为当前实现；前述目标策略不能直接视为现有 `Policy` 已支持的字段或行为。

### Manager 接口

- `NewManager(Store, Policy)` 创建 Manager；Service 使用 DefaultPolicy，允许通过 Config.ProxyPolicy 注入策略。
- `ResolveProxy(ctx, groupID, application, tried)` 返回不可变 Endpoint；空 groupID 返回 nil。Endpoint 内部保存半开租约，调用方必须将选中对象交回 ReportProxy，包括取消分支。
- `ReportProxy(endpoint, application, class)` 接收 success（空字符串）、network、application、application_ignored、canceled。网络错误只改变网络健康；应用错误只改变该应用健康。`application_ignored` 表示网络可达，但该结果不能判断共享代理的应用健康（例如用户凭据失效），不计入应用健康样本，也不清除应用熔断。网络探测不能恢复应用熔断。
- `List/New/Save/Delete` 管理组；`New` 创建组并由存储分配 ID，`Save` 更新已有组。组 Enabled 省略时启用，地址顺序表示优先级。旧健康字段保持 JSON 兼容，但不作为调度输入；未知状态允许首次真实请求验证。
- `Test/TestURL` 主动探测，`SetProber` 可注入探测器；默认探测使用 HTTPS 请求确认网络路径，不将目标 HTTP 状态当成应用恢复依据。
- `Snapshot/Recent/History` 分别返回全局健康快照、最近 10 个分钟桶和历史聚合；`ErrorRecords` 为原管理 API 提供网络错误桶视图。

### 默认策略与配置边界

默认策略为：统计窗口 5 分钟、最小样本 5、网络／应用失败率阈值各 50%、连续失败阈值各 3、网络初始冷却 30 秒、应用冷却 5 分钟、网络／应用恢复各需连续成功 2 次、半开并发 1。自动网络探测默认开启，并发上限 4，失败退避封顶 10 分钟，采用 90%～100% 的有界抖动；探测超时 12 秒。待持久化聚合桶上限为 10000。

所有参数可通过 `Config.ProxyPolicy` 注入；`FailureThreshold` 保留为网络／应用连续失败阈值未分别填写时的回退值，失败率阈值设为 0 可关闭对应失败率判断。非法策略在构造时拒绝。当前策略按 Manager 全局生效，不提供存在歧义的组级健康覆盖。半开采用确定性的并发配额，而非概率放行。实时健康计数保持进程生命周期，分钟桶限制最近 10 分钟；重启不恢复内存熔断状态。

### 探测与管理状态

`Test/TestURL` 与自动任务共用网络恢复状态，单地址不能同时探测与执行网络半开请求。探测只累计 `probe_requests/probe_failures`，不混入业务网络或应用样本。管理组列表返回每个地址的 `network` 与 `applications` 状态快照；前端可调整地址顺序并查看应用状态。

### 日志输出与错误上报

使用 Common 的模块 Logger，模块标识为 `proxy`，输出仅包含 `time`、`level`、`module`、`event`、`msg`；操作详情以 `key=value` 文本写入 `msg`。请求错误使用 `proxy_error`（WARN）；调度、探测、配置及存储操作失败使用 `operation_failed`（ERROR）；取消及关闭分别使用 `request_canceled`、`operation_canceled`、`manager_closed`（INFO），状态变化使用 INFO。调度失败附原因及禁用、已尝试、网络／应用不可准入的候选数量，不逐条输出正常跳过日志。自动探测和定时刷新失败同样记录。

状态变化使用 `state_changed`，包含代理地址、网络／应用作用域、应用标识、旧／新状态、来源、原因及冷却、退避、半开占用等信息；状态不变但冷却截止时间变化时使用 `cooldown_updated`。正常请求反复保持可用不输出状态日志。

`ReportProxy` 保持兼容；`ReportProxyResult(endpoint, application, class, cause, status)` 可额外接收原始错误与 HTTP 状态码，仅用于日志，不改变分类和健康判断。AIProvider 通过 `proxy.ReportResult` 优先使用详细上报接口，旧 resolver 则由该辅助函数记录错误后调用原接口；每次重试和认证恢复前的失败分别上报。响应读取失败由调用方通过 `proxy.LogError` 记录，不重复更新健康统计。

日志中的代理地址仅展示协议及主机端口，错误中的 URL、凭据和令牌字段统一脱敏；不传入请求／响应正文或认证头。日志输出不代表新增数据库逐次错误或状态事件存储。

### 持久化与关闭

每分钟刷新历史聚合。SQLite 用地址、应用、10 分钟桶及进程来源作唯一键，保存绝对计数快照；相同来源的重复写入覆盖，不重复累计。写入成功后移除已结束的聚合桶，当前桶保留用于后续覆盖更新；失败保留待写数据。容量不足时阻止新增统计序列及相应代理请求，返回错误，不无限积压。Close 取消自有探测、停止刷新任务、等待探测结束并刷新统计；失败可重试，成功后重复关闭安全。

Store 包含组读写与聚合统计读写，可选 `HealthStore` 提供健康快照落库；MemoryDatabase 和 SQLiteDatabase 均实现该扩展。Database 通过领域类型及 SQLite 事务实现契约。管理路由继续为 `/api/proxy-groups`，见 [API](unisub-api.md)。

## 设计验证边界

测试覆盖地址构造、并发传输隔离、跨组状态、优先级、网络与应用隔离、半开租约、Context 取消、统计时间窗、持久化失败及重复聚合。SQLite 测试验证重启与幂等统计；OAuth 测试验证 Session 代理绑定。模拟测试不等同于真实外部代理或平台验证。

新增测试覆盖最小样本与失败率阈值、网络／应用独立冷却、主动探测不恢复应用、无真实流量不恢复应用、连续多次成功恢复、统计过期不解除熔断、探测不混入业务统计，以及健康快照幂等落库和重启边界。
